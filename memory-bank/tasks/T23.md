## Description
The process-monitor services (monitor and dashboard) were failing because `tsx` was not available in the runtime environment. The LaunchAgents referenced `/Users/sage/.nvm/versions/node/v22.22.3/bin/tsx` which no longer existed. This caused cascading failures where cron jobs tried to restart services every 10 minutes but failed, creating EADDRINUSE loops.

This task compiles TypeScript to JavaScript, replaces tsx with plain node, and fixes ESM/CJS incompatibilities discovered during compilation.

## Notes
- `better-sqlite3` uses the `bindings` npm package to dynamically locate its `.node` file at runtime. This prevents `bun build --compile` from working as a fully standalone binary.
- To achieve fully standalone compilation, would need to either:
  1. Replace `better-sqlite3` with `bun:sqlite` (bun's built-in SQLite)
  2. Or ship the native `.node` alongside the binary
- Current solution eliminates tsx dependency while keeping runtime deps in node_modules (systeminformation, better-sqlite3, qrcode). This is the practical sweet spot.
