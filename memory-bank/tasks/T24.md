## Description
Improve process-monitor so a future macOS kernel watchdog incident can be
investigated using historical memory, compression, paging, swap, process, and
sampling evidence. The records are observations and correlations only; they do
not attribute a kernel panic to Codex, OpenClaw, or any other process.

## Acceptance Criteria
- [x] Sample at a configurable interval with a 15-second default.
- [x] Record UTC/IST timestamps, memory pressure, swap usage, vm_stat counters,
      available memory, load, uptime, and bounded process evidence.
- [x] Sanitize command-line data and classify relevant process families.
- [x] Persist snapshots and process rows in one durable SQLite transaction.
- [x] Bound history/API responses and add atomic incident bundles.
- [x] Add observation alerts with hysteresis for pressure, swap, paging,
      relevant process load, churn, and sampling gaps.
- [x] Add focused parser, alert, sanitization, gap, and API-size tests.
- [x] Verify the updated build is deployed in the separate sage service
      checkout with a matching better-sqlite3 runtime.
- [x] Dashboard UI: Watchdog tab with active alerts, incident actions, and alert history
      (implemented 2026-09-01 22:25 IST)

## Implementation Details
- `WatchdogEvidence.ts` parses macOS `memory_pressure`, `vm.swapusage`, and
  `vm_stat` output and collects argument-free `ps` process rows.
- `WatchdogAlertDetector.ts` emits transition alerts with configurable
  hysteresis and observation-only wording.
- `TimeSeriesDB.ts` adds host evidence columns, sanitized process provenance,
  `watchdog_alerts`, bounded queries, transactional writes, and atomic bundles.
- `/api/snapshot` and `/api/history` expose the evidence fields. New
  `/api/evidence-alerts` and `/api/incident-bundle` routes expose alerts and
  manual bundle creation.
- `ResponseLimit.ts` caps JSON responses at 2 MB.
- **Dashboard UI (added 2026-09-01 22:25 IST):**
  - New "🚨 Watchdog" tab (7th tab) in `web/public/index.html`
  - `loadWatchdogAlerts()` — fetches `/api/evidence-alerts`, renders severity-colored cards
  - `createIncidentBundle()` — POSTs to `/api/incident-bundle` with alert context
  - `loadIncidentBundles()` — lists saved bundles and provides downloads
  - Auto-refresh every 30s when Watchdog tab is active
  - CSS: `.watchdog-alert-item` with severity borders (red=critical, yellow=warning, blue=info)
  - Cache-busted: `styles.css?v=5`, `app.js?v=9`
- The compiled monitor launcher remains under the existing LaunchDaemon
  ownership model and uses `dist/main.js`.
